La prima vista#

Progetto di esempio examples/Sources/01-HelloView, si esegue con swift run HelloView. Scarica tutti gli esempi oppure guarda come eseguirli.

È il momento del primo codice Metal: un renderer che a ogni frame riempie la finestra con un colore.
Non disegna geometria, ma contiene lo scheletro completo di un frame, e ogni capitolo successivo non fa che aggiungervi qualcosa.

Leggere questo capitolo in C++

In metal-cpp non ci sono né MTKView né delegate.
Il tuo renderer tiene il CAMetalLayer di Preparare il progetto, e main.cpp chiama renderer.draw() una volta per ciclo.
Dove il testo dice view.currentDrawable, tu chiami layer->nextDrawable().
Dove dice view.currentRenderPassDescriptor, compili tu un MTL::RenderPassDescriptor, e così le load e store action spiegate più sotto diventano visibili nel tuo codice.

Il renderer#

Crea Renderer.swift:

import MetalKit

final class Renderer: NSObject, MTKViewDelegate {
    let device: MTLDevice
    let commandQueue: MTLCommandQueue

    init?(view: MTKView) {
        guard let device = MTLCreateSystemDefaultDevice(),
              let commandQueue = device.makeCommandQueue() else {
            return nil
        }
        self.device = device
        self.commandQueue = commandQueue
        super.init()

        view.device = device
        view.colorPixelFormat = .bgra8Unorm
        view.clearColor = MTLClearColor(red: 0.2, green: 0.3, blue: 0.3, alpha: 1.0)
        view.delegate = self
    }

    func mtkView(_ view: MTKView, drawableSizeWillChange size: CGSize) {
        // Called when the view is resized. We will need it for the projection matrix later.
    }

    func draw(in view: MTKView) {
        guard let passDescriptor = view.currentRenderPassDescriptor,
              let drawable = view.currentDrawable,
              let commandBuffer = commandQueue.makeCommandBuffer(),
              let encoder = commandBuffer.makeRenderCommandEncoder(descriptor: passDescriptor) else {
            return
        }

        // Draw calls will go here.

        encoder.endEncoding()
        commandBuffer.present(drawable)
        commandBuffer.commit()
    }
}

// Renderer.hpp
#pragma once
#include <Metal/Metal.hpp>
#include <QuartzCore/QuartzCore.hpp>

class Renderer {
public:
    Renderer(MTL::Device* device, CA::MetalLayer* layer);
    ~Renderer();

    // Called when the window is resized. We will need it for the projection matrix later.
    void resize(int width, int height) {}
    void draw();

private:
    MTL::Device* device;
    MTL::CommandQueue* commandQueue;
    CA::MetalLayer* layer;
};

// Renderer.cpp
#include "Renderer.hpp"

Renderer::Renderer(MTL::Device* device, CA::MetalLayer* layer)
    : device(device->retain()), layer(layer) {
    commandQueue = device->newCommandQueue();
    layer->setPixelFormat(MTL::PixelFormatBGRA8Unorm);
}

Renderer::~Renderer() {
    commandQueue->release();
    device->release();
}

void Renderer::draw() {
    // Objects returned by methods that do not start with new/alloc are autoreleased.
    NS::AutoreleasePool* pool = NS::AutoreleasePool::alloc()->init();

    CA::MetalDrawable* drawable = layer->nextDrawable();
    if (drawable) {
        // There is no MTKView to hand us a descriptor, so we describe the pass ourselves.
        MTL::RenderPassDescriptor* passDescriptor = MTL::RenderPassDescriptor::alloc()->init();
        MTL::RenderPassColorAttachmentDescriptor* color = passDescriptor->colorAttachments()->object(0);
        color->setTexture(drawable->texture());
        color->setLoadAction(MTL::LoadActionClear);
        color->setClearColor(MTL::ClearColor::Make(0.2, 0.3, 0.3, 1.0));
        color->setStoreAction(MTL::StoreActionStore);

        MTL::CommandBuffer* commandBuffer = commandQueue->commandBuffer();
        MTL::RenderCommandEncoder* encoder = commandBuffer->renderCommandEncoder(passDescriptor);

        // Draw calls will go here.

        encoder->endEncoding();
        commandBuffer->presentDrawable(drawable);
        commandBuffer->commit();
        passDescriptor->release();
    }
    pool->release();
}

Eseguilo.
Dovresti vedere una finestra riempita di verde petrolio scuro.

Il device e la coda#

MTLCreateSystemDefaultDevice() restituisce la GPU consigliata dal sistema.
Su Apple silicon ce n'è una sola.
Tutto il resto viene creato a partire da questo device.

La command queue si crea una volta e si tiene per tutta la vita dell'app.
Garantisce che i command buffer di cui fai il commit vengano eseguiti in ordine.

Configurare la vista#

  • view.device dice alla vista su quale GPU vivono le sue texture.
    Senza, non viene disegnato nulla.
  • colorPixelFormat è il formato della texture mostrata a schermo.
    .bgra8Unorm significa quattro canali a 8 bit memorizzati come blu, verde, rosso, alfa, che gli shader leggono come float da 0 a 1.
    È il valore predefinito della vista; lo impostiamo in modo esplicito perché lo cambieremo nel capitolo Correzione gamma.
  • clearColor è il colore con cui il drawable viene riempito all'inizio di ogni frame.

Anatomia di un frame#

draw(in:) viene chiamato una volta per ogni aggiornamento dello schermo, di solito 60 o 120 volte al secondo.
Dentro succedono quattro cose.

1. Ottenere un render pass descriptor.
Un render pass è un blocco di disegno diretto a un insieme di texture, i suoi attachment.
currentRenderPassDescriptor è un descriptor già pronto il cui attachment di colore è la texture del drawable di questo frame.
Per ogni attachment un descriptor contiene anche:

  • una load action: che cosa fare del contenuto esistente quando il pass inizia (.clear, .load o .dontCare),
  • una store action: che cosa fare del risultato quando finisce (.store, .dontCare o un multisample resolve).

Il descriptor della vista usa .clear con il tuo clearColor, e .store.
Ecco perché otteniamo una finestra colorata senza disegnare niente: la pulizia fa parte dell'inizio del pass.

Se vieni da OpenGL

Non esiste una chiamata glClear.
La pulizia è una proprietà del render pass, e scegliere bene le load e store action conta per le prestazioni sulle GPU tile-based, perché ognuna può far risparmiare o costare una copia intera della texture.

2. Creare un command buffer e un encoder.
Il command buffer conserva i comandi codificati per questo frame.
Il render command encoder traduce le tue chiamate (imposta la pipeline, imposta il buffer, disegna) in comandi GPU per questo singolo pass.

3. Chiudere l'encoding.
Devi chiamare endEncoding() prima di creare un altro encoder o di fare il commit.
Dimenticarlo è un errore di validazione.

4. Presentare e fare il commit.
present(drawable) programma la visualizzazione del drawable non appena la GPU finisce questo command buffer.
commit() consegna il buffer alla coda.
La chiamata ritorna subito; la GPU lavora in modo asincrono.

I drawable sono pochi#

currentDrawable arriva da un piccolo gruppo, di solito tre texture.
Se sono tutte in uso, la chiamata resta in attesa finché una non si libera, e può restituire nil.
Per questo il metodo inizia con un guard e salta semplicemente il frame quando manca qualcosa.
Tieni un drawable per il minor tempo possibile e non conservarlo mai.

Continuo o su richiesta#

In modo predefinito MTKView ridisegna di continuo a preferredFramesPerSecond.
Per un'app in stile editor, che cambia solo quando arriva un input, puoi impostare view.isPaused = true e view.enableSetNeedsDisplay = true, e poi chiedere i frame con setNeedsDisplay.
Un gioco o un'animazione tengono il comportamento predefinito.

Esercizi#

  • Cambia il colore di sfondo a ogni frame usando CACurrentMediaTime() e sin, in modo che la finestra pulsi.
    Mostra la soluzione

    Calcola il colore nel metodo di disegno, prima di chiedere il render pass descriptor, perché il descriptor copia il colore di sfondo nel momento in cui lo leggi.
    In Swift: let t = sin(CACurrentMediaTime()) * 0.5 + 0.5 e poi view.clearColor = MTLClearColor(red: 0.2 * t, green: 0.3, blue: 0.3 * t, alpha: 1).
    In C++ fai lo stesso calcolo con glfwGetTime() e passa il risultato a setClearColor.

  • Stampa view.drawableSize in mtkView(_:drawableSizeWillChange:) e ridimensiona la finestra.
    Nota che la dimensione è in pixel, non in punti: su uno schermo Retina è il doppio di quella della finestra.
    Mostra la soluzione

    La callback riceve la dimensione in pixel.
    Una finestra di 800 × 600 punti su uno schermo Retina riporta 1600 × 1200.
    In Metal tutto (viewport, dimensioni delle texture, in.position.xy in una fragment function) è in pixel, quindi ricava sempre i rapporti d'aspetto e le dimensioni delle texture offscreen da questo valore e mai dalla dimensione in punti della finestra.
