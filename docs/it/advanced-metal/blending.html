Metal avanzato

Blending#

Il blending è il modo in cui si fa la trasparenza.
Invece di sostituire il colore già presente nella texture, il colore di un nuovo fragment viene combinato con esso.
La quarta componente del colore, l'alpha, di solito decide come: 1 è del tutto opaco, 0 è del tutto trasparente.

Scartare i fragment#

Alcune immagini sono o del tutto opache o del tutto trasparenti, come una texture d'erba o di foglie con una sagoma ritagliata.
Non hanno bisogno di blending.
La fragment function può semplicemente buttare via i fragment trasparenti:

fragment float4 fragment_cutout(VertexOut in [[stage_in]],
                                texture2d<float> colorTexture [[texture(0)]],
                                sampler textureSampler [[sampler(0)]]) {
    float4 color = colorTexture.sample(textureSampler, in.uv);
    if (color.a < 0.1) {
        discard_fragment();
    }
    return color;
}

Un fragment scartato non scrive né colore né profondità.
Carica queste texture con un sampler che usa .clampToEdge; con .repeat il filtro lineare mescola la riga in alto con quella in basso e lascia una linea leggera sul bordo.

Sulle GPU tile-based discard_fragment impedisce alcune ottimizzazioni di rimozione delle superfici nascoste, quindi usalo solo nelle pipeline che ne hanno bisogno.

L'equazione di blending#

Per le superfici semitrasparenti come il vetro la pipeline calcola

result = source * sourceFactor  (op)  destination * destinationFactor

dove source è l'uscita della fragment function e destination è il colore già salvato.
In Metal il blending fa parte del render pipeline state e si configura per ogni attachment di colore:

let attachment = pipelineDescriptor.colorAttachments[0]!
attachment.isBlendingEnabled = true
attachment.rgbBlendOperation = .add
attachment.alphaBlendOperation = .add
attachment.sourceRGBBlendFactor = .sourceAlpha
attachment.destinationRGBBlendFactor = .oneMinusSourceAlpha
attachment.sourceAlphaBlendFactor = .one
attachment.destinationAlphaBlendFactor = .oneMinusSourceAlpha

MTL::RenderPipelineColorAttachmentDescriptor* attachment = pipelineDescriptor->colorAttachments()->object(0);
attachment->setBlendingEnabled(true);
attachment->setRgbBlendOperation(MTL::BlendOperationAdd);
attachment->setAlphaBlendOperation(MTL::BlendOperationAdd);
attachment->setSourceRGBBlendFactor(MTL::BlendFactorSourceAlpha);
attachment->setDestinationRGBBlendFactor(MTL::BlendFactorOneMinusSourceAlpha);
attachment->setSourceAlphaBlendFactor(MTL::BlendFactorOne);
attachment->setDestinationAlphaBlendFactor(MTL::BlendFactorOneMinusSourceAlpha);

È il classico alpha blending: risultato = source * alpha + destination * (1 - alpha).
Una finestra rossa con alpha 0.5 davanti a un muro verde dà una miscela in parti uguali dei due.

Altre configurazioni utili:

Effetto Fattore source Fattore destination
Alpha blending .sourceAlpha .oneMinusSourceAlpha
Alpha premoltiplicato .one .oneMinusSourceAlpha
Additivo (fuoco, bagliori) .one o .sourceAlpha .one
Moltiplicativo (tinta, ombra) .destinationColor .zero

Se vieni da OpenGL

Non c'è un glEnable(GL_BLEND) da accendere e spegnere tra una draw call e l'altra.
Crei un pipeline state per il disegno opaco e un altro per il disegno con blending, e cambi pipeline state.

Alpha premoltiplicato

Molti loader di immagini, Core Graphics compreso, consegnano i colori già moltiplicati per il loro alpha.
Fare il blending di una texture così con .sourceAlpha scurisce i bordi.
Per i contenuti premoltiplicati usa .one come fattore source.

L'ordine conta#

Blending e depth buffer non collaborano.
Se una finestra viene disegnata per prima scrive la sua profondità, e tutto ciò che viene disegnato dopo dietro di lei viene scartato dal test di profondità, anche se dovrebbe vedersi attraverso il vetro.
La regola per un'immagine corretta:

  1. Disegna prima tutti gli oggetti opachi.
  2. Ordina gli oggetti trasparenti per distanza dalla camera.
  3. Disegnali da dietro in avanti, con il test di profondità acceso e la scrittura della profondità spenta.
let sortedWindows = windowPositions.sorted {
    distance_squared(camera.position, $0) > distance_squared(camera.position, $1)
}

encoder.setRenderPipelineState(blendPipelineState)
encoder.setDepthStencilState(depthTestNoWriteState)
for position in sortedWindows {
    uniforms.model = float4x4(translation: position)
    encoder.setVertexBytes(&uniforms, length: MemoryLayout<Uniforms>.stride, index: 1)
    encoder.drawPrimitives(type: .triangle, vertexStart: 0, vertexCount: 6)
}

std::vector<simd::float3> sortedWindows = windowPositions;
std::sort(sortedWindows.begin(), sortedWindows.end(), [&](simd::float3 a, simd::float3 b) {
    return simd::distance_squared(camera.position, a) > simd::distance_squared(camera.position, b);
});

encoder->setRenderPipelineState(blendPipelineState);
encoder->setDepthStencilState(depthTestNoWriteState);
for (simd::float3 position : sortedWindows) {
    uniforms.model = translation(position);
    encoder->setVertexBytes(&uniforms, sizeof(Uniforms), 1);
    encoder->drawPrimitives(MTL::PrimitiveTypeTriangle, NS::UInteger(0), NS::UInteger(6));
}

Ordinare per distanza dell'oggetto non è perfetto.
Superfici trasparenti che si intersecano, o molto grandi, possono ancora mescolarsi nell'ordine sbagliato.
Le tecniche che eliminano la necessità di ordinare vanno sotto il nome di order-independent transparency.
Le GPU Apple ne rendono praticabile una famiglia grazie al programmable blending, in cui una fragment function può leggere il colore attuale del pixel che sta scrivendo; incontrerai questa funzione in Deferred shading.

Esercizi#

  • Disegna dei rettangoli d'erba con discard_fragment, poi con il blending ma senza ordinamento, e confronta i bordi.
    Mostra la soluzione

    Con discard_fragment i bordi sono netti: un pixel è dentro o fuori, e dove l'alpha della texture è parziale si vedono i gradini.
    Con il blending i bordi sono morbidi, ma senza ordinamento un rettangolo più vicino disegnato per primo scrive la profondità e ritaglia buchi rettangolari nell'erba che gli sta dietro.
    Le sagome ritagliate vogliono il discard (o l'alpha-to-coverage); la vera trasparenza vuole il blending con l'ordinamento.

  • Disegna le finestre da davanti verso dietro per vedere l'artefatto che l'ordinamento evita.
    Mostra la soluzione

    La finestra più vicina viene disegnata per prima e scrive la sua profondità.
    Ogni finestra dietro di lei fallisce allora il test di profondità, e quindi manca dove quella vicina la copre, anche se dovresti vederla attraverso il vetro.
    Nella demo interattiva togli la spunta a "sort back to front" e mettila a "windows write depth".

  • Crea una pipeline additiva per le particelle e disegna qualche rettangolo sovrapposto.
    Mostra la soluzione

    Attiva il blending con fattore source .one (o .sourceAlpha) e fattore destination .one, e spegni la scrittura della profondità.
    I colori si sommano, quindi i rettangoli sovrapposti diventano più luminosi, e l'ordine non conta più, perché la somma è commutativa.
    Ecco perché le particelle additive non hanno bisogno di ordinamento.
