In pratica

Engine: il gioco#

Il renderer disegna qualunque cosa ci sia nella scena.
Questo capitolo parla di ciò che le cose ce le mette e le fa muovere: entità, fisica, input, suono, un'interfaccia.
L'esempio è Marble, il gioco che accompagna il LearnMetal Engine.
Tutto quanto, livello compreso, sta in circa ottocento righe, e quasi ogni riga è una chiamata a qualcosa che questo capitolo spiega.

Entità e componenti#

Un'entità non è altro che un id.
Tutto ciò che la rende una biglia, una lampada o un muro sta nei suoi componenti: semplici struct, conservate dalla scena.
L'engine porta quelli per cui ha dei sistemi: Transform, Camera, Light, MeshRenderer, RigidBody, Collider, ParticleEmitter.
Un gioco aggiunge i suoi, e non c'è bisogno di farli conoscere all'engine:

/// Something to collect. The entity also carries a mesh, a light and a trigger collider.
struct Gem {
    var home: Vec3              // the gem bobs up and down around this point
    var phase: Float            // so that the gems do not all move in step
    var color: Vec3
}

/// A platform that glides back and forth between two points.
struct MovingPlatform {
    var from: Vec3
    var to: Vec3
    var period: Float           // seconds for a round trip
}

/// Destroys its entity when the time runs out: for one-shot effects.
struct Lifetime {
    var seconds: Float
}

/// Something to collect. The entity also carries a mesh, a light and a trigger collider.
struct Gem {
    lm::Vec3 home{0, 0, 0};         // the gem bobs up and down around this point
    float phase = 0;                // so that the gems do not all move in step
    lm::Vec3 color{1, 1, 1};
};

/// A platform that glides back and forth between two points.
struct MovingPlatform {
    lm::Vec3 from{0, 0, 0};
    lm::Vec3 to{0, 0, 0};
    float period = 6;               // seconds for a round trip
};

/// Destroys its entity when the time runs out: for one-shot effects.
struct Lifetime {
    float seconds = 1;
};

Non esiste una classe Gem con un metodo di disegno e uno di aggiornamento.
Una gemma è un'entità a cui vengono dati cinque componenti, e ognuno fa sì che una parte diversa dell'engine si accorga di lei:

for position in gemPositions {
    let index = level.gemCount
    level.gemCount += 1
    let color = gemColors[index % 4]
    let gem = scene.create("Gem")
    scene.add(gem, Transform(position: position, scale: Vec3(0.9, 0.9, 0.9)))
    scene.add(gem, MeshRenderer(mesh: gemMesh, material: gemMaterials[index % 4]))
    scene.add(gem, Gem(home: position, phase: 0.9 * Float(index), color: color))
    scene.add(gem, Light(type: .point, color: color, intensity: 5, range: 5))
    var trigger = Collider.sphere(radius: 0.75)
    trigger.isTrigger = true
    scene.add(gem, trigger)
}

for (const Vec3& position : gemPositions) {
    int index = level.gemCount++;
    Entity gem = scene.create("Gem");
    Transform transform;
    transform.position = position;
    transform.scale = Vec3{0.9f, 0.9f, 0.9f};
    scene.add(gem, transform);
    scene.add(gem, MeshRenderer{gemMesh, gemMaterials[index % 4]});
    scene.add(gem, Gem{position, 0.9f * float(index), gemColors[index % 4]});
    Light light;
    light.color = gemColors[index % 4];
    light.intensity = 5.0f;
    light.range = 5.0f;
    scene.add(gem, light);
    Collider trigger = Collider::sphere(0.75f);
    trigger.isTrigger = true;
    scene.add(gem, trigger);
}

Il renderer vede una mesh e una luce.
La fisica vede un trigger.
Solo il gioco vede una Gem.

Il comportamento, quindi, è un ciclo su tutto ciò che ha i componenti giusti.
Questo è l'intera animazione delle gemme:

// Gems turn and bob; their lights and triggers move with them.
let time = Float(engine.time.elapsed)
scene.each(Gem.self, Transform.self) { _, gem, transform in
    transform.position = gem.home + Vec3(0, 0.18 * sin(time * 2 + gem.phase), 0)
    transform.rotation = Quat(angle: time * 1.4 + gem.phase, axis: Vec3(0, 1, 0))
}

// Gems turn and bob; their lights and triggers move with them.
float time = float(engine.time.elapsed);
scene.each<Gem, Transform>([&](Entity, Gem& gem, Transform& transform) {
    transform.position = gem.home + Vec3{0, 0.18f * std::sin(time * 2.0f + gem.phase), 0};
    transform.rotation = axisAngle(Vec3{0, 1, 0}, time * 1.4f + gem.phase);
});

Dentro la scena i componenti di uno stesso tipo stanno uno dietro l'altro in un unico array, quindi un ciclo come questo legge la memoria in ordine.
Il componente Lifetime funziona allo stesso modo: un ciclo lo fa scendere e a zero distrugge l'entità.
Distruggere dentro un ciclo è sempre sicuro, perché l'entità viene rimossa davvero solo alla fine del passo, come ha mostrato il primo capitolo.

C'è un dettaglio di Swift che conta ovunque nel codice di gioco.
I componenti sono valori.
scene[entity, RigidBody.self] ti dà una copia, quindi o lo modifichi sul posto attraverso il subscript, come in scene[cube, Transform.self]?.rotation = ..., oppure ne prendi una copia, la modifichi e la salvi di nuovo.
Dentro each i parametri della closure sono inout: ciò che cambi lì viene salvato.

C'è un dettaglio del C++ che conta ovunque nel codice di gioco.
scene.get<RigidBody>(entity) restituisce un puntatore dentro la memoria della scena, oppure nullptr.
Il puntatore resta valido finché non viene aggiunto o rimosso un componente dello stesso tipo, quindi usalo e lascialo andare; non tenerlo in una variabile membro.

Corpi, collider e trigger#

Un Collider dà a un'entità una forma: una sfera, una scatola o una capsula.
Da solo è un ostacolo statico, che è tutto ciò che serve a un pavimento o a un muro.
Aggiungi un RigidBody e l'entità si muove.
Il livello di Marble è fatto di scatole con collider; la rampa è semplicemente una scatola inclinata.

scene.add(level.marble, Collider.sphere(radius: Level.marbleRadius))
var marbleBody = RigidBody(restitution: 0.35, friction: 0.03)      // a rolling ball barely slows down by itself
marbleBody.linearDamping = 0.15
scene.add(level.marble, marbleBody)

scene.add(level.marble, Collider::sphere(Level::kMarbleRadius));
RigidBody marbleBody;
marbleBody.restitution = 0.35f;
marbleBody.friction = 0.03f;                // a rolling ball barely slows down by itself
marbleBody.linearDamping = 0.15f;
scene.add(level.marble, marbleBody);

La fisica è del tipo che vuole la maggior parte dei giochi, a volte chiamata fisica arcade: gravità, rimbalzi, attrito, cose che si spingono a vicenda e si impilano.
Lascia fuori di proposito le parti difficili.
I corpi non ruotano quando vengono colpiti, non ci sono giunti, e un oggetto molto veloce può attraversarne uno sottile.
Quando a un gioco servono queste cose, lo strumento giusto è una libreria di fisica dedicata.

La prima di queste mancanze stonerebbe su una biglia: una palla che scivola senza girare.
Quindi la fa girare il gioco, esattamente dell'angolo di cui una palla di quella dimensione ruota percorrendo quella distanza:

// The physics moves the marble but does not spin it. Turn it by the angle a ball of
// this size rolls through when it travels this far: distance divided by radius.
let flat = Vec3(body.velocity.x, 0, body.velocity.z)
let speed = simd_length(flat)
if speed > 0.05, let rotation = scene[level.marble, Transform.self]?.rotation {
    let axis = simd_normalize(simd_cross(Vec3(0, 1, 0), flat))
    let roll = Quat(angle: speed * dt / Level.marbleRadius, axis: axis)
    scene[level.marble, Transform.self]?.rotation = simd_normalize(roll * rotation)
}

// The physics moves the marble but does not spin it. Turn it by the angle a ball of
// this size rolls through when it travels this far: distance divided by radius.
Vec3 flat{body->velocity.x, 0, body->velocity.z};
float speed = simd::length(flat);
if (speed > 0.05f) {
    Vec3 axis = simd::normalize(simd::cross(Vec3{0, 1, 0}, flat));
    marble->rotation = simd::normalize(axisAngle(axis, speed * dt / Level::kMarbleRadius) * marble->rotation);
}

Nessuno, guardando, può capire che la rotazione è decorazione.
Gran parte della programmazione di giochi è questo: simulare ciò che conta e fingere il resto in modo convincente.

Un collider marcato come trigger non blocca niente.
Riporta soltanto che cosa gli entra dentro.
È così che il gioco sa che una gemma è stata toccata o che il traguardo è stato raggiunto:

// Physics events. They arrive at the end of a physics step.
engine.physics.onTriggerEnter = { [unowned self, unowned engine] trigger, other in
    if other != self.level.marble { return }
    if engine.scene.has(Gem.self, trigger) {
        self.collect(engine, trigger)
    } else if trigger == self.level.goal && self.collectedCount == self.level.gemCount && !self.hasWon {
        self.hasWon = true
        engine.audio.play(self.sounds.win)
        if let goal = engine.scene[self.level.goal, Transform.self] {
            self.spawnBurst(engine, position: goal.position + Vec3(0, 0.5, 0), color: Vec3(0.4, 1.0, 0.5))
        }
    }
}
engine.physics.onContactBegin = { [unowned self, unowned engine] contact in
    if contact.a != self.level.marble && contact.b != self.level.marble { return }
    if contact.impactSpeed < 2.5 { return }
    let volume = saturate(contact.impactSpeed / 12)     // harder hits are louder
    engine.audio.play(self.sounds.land, options: PlayOptions(volume: volume, pitch: 0.9 + 0.2 * volume))
}

// Physics events. They arrive at the end of a physics step.
engine.physics.onTriggerEnter = [this, &engine](Entity trigger, Entity other) {
    if (other != level_.marble) return;
    if (engine.scene.has<Gem>(trigger)) {
        collect(engine, trigger);
    } else if (trigger == level_.goal && collected_ == level_.gemCount && !hasWon_) {
        hasWon_ = true;
        engine.audio().play(sounds_.win);
        spawnBurst(engine, engine.scene.get<Transform>(level_.goal)->position + Vec3{0, 0.5f, 0}, Vec3{0.4f, 1.0f, 0.5f});
    }
};
engine.physics.onContactBegin = [this, &engine](const Contact& contact) {
    if (contact.a != level_.marble && contact.b != level_.marble) return;
    if (contact.impactSpeed < 2.5f) return;
    PlayOptions options;
    options.volume = saturate(contact.impactSpeed / 12.0f);     // harder hits are louder
    options.pitch = 0.9f + 0.2f * options.volume;
    engine.audio().play(sounds_.land, options);
};

Il secondo evento scatta quando due cose solide cominciano a toccarsi, e dice a che velocità si sono incontrate.
Il gioco lo usa per una cosa sola: un tonfo il cui volume dipende da quanto forte è atterrata la biglia.

Input: leggi una volta, usa dopo#

Il gioco non chiede mai se il tasto W è premuto.
Definisce una volta delle azioni, e da quel momento chiede di quelle:

input.bindAxis("lookX", negative: .left, positive: .right, gamepadAxis: .rightX)
input.bindAxis("lookY", negative: .down, positive: .up, gamepadAxis: .rightY)
input.bindButton("jump", keys: [.space], buttons: [.a])
input.bindButton("restart", keys: [.r], buttons: [.start])
input.bindButton("quit", keys: [.escape], buttons: [.back])

Tastiera e gamepad alimentano la stessa azione, quindi supportarli entrambi non costa niente di più.

Il primo capitolo avvertiva che il passo fisso è il posto sbagliato per leggere l'input, perché gira zero, una o più volte per frame.
Quindi update legge, e ricorda:

// Input is read here, once per frame, and remembered for the fixed steps.
if !isDemo {
    wish = Vec2(input.axis("moveX"), input.axis("moveY"))
    let length = simd_length(wish)
    if length > 1 { wish /= length }                // diagonals are not faster
    if input.wasPressed("jump") { jumpBuffer = 0.15 }
    if length > 0.1 { hasMoved = true }
}

// Input is read here, once per frame, and remembered for the fixed steps.
if (!isDemo) {
    wish_ = Vec2{input.axis("moveX"), input.axis("moveY")};
    float length = simd::length(wish_);
    if (length > 1.0f) wish_ /= length;             // diagonals are not faster
    if (input.wasPressed("jump")) jumpBuffer_ = 0.15f;
    if (length > 0.1f) hasMoved_ = true;
}

Un salto non viene ricordato come "sì" ma come "sì, per i prossimi 0.15 secondi".
Premi il pulsante un attimo prima che la biglia atterri e salterà comunque all'atterraggio.
I giocatori non se ne accorgono mai; si accorgono solo dei giochi che non lo fanno.

fixedUpdate trasforma poi in movimento ciò che è stato ricordato:

// Push the marble where the stick points, relative to where the camera looks.
// (The autopilot thinks in compass directions instead: east and north.)
if !hasWon {
    var forward = Vec3(-sin(cameraYaw), 0, -cos(cameraYaw))
    var right = Vec3(cos(cameraYaw), 0, -sin(cameraYaw))
    if isDemo {
        let command = autopilot.steer(engine, level)
        wish = command.push
        if command.jump { jumpBuffer = 0.15 }
        forward = Vec3(0, 0, -1)
        right = Vec3(1, 0, 0)
        if simd_length(wish) > 0.1 { hasMoved = true }
    }
    let push = right * wish.x + forward * wish.y
    let control: Float = body.isGrounded ? 1 : airControl
    body.velocity += push * (acceleration * control * dt)

    // A speed limit on the ground plane only, so that falling stays fast.
    var flat = Vec3(body.velocity.x, 0, body.velocity.z)
    let speed = simd_length(flat)
    if speed > maxSpeed {
        flat *= maxSpeed / speed
        body.velocity = Vec3(flat.x, body.velocity.y, flat.z)
    }

    jumpBuffer -= dt
    if jumpBuffer > 0 && body.isGrounded {
        body.velocity.y = jumpSpeed
        jumpBuffer = 0
        engine.audio.play(sounds.jump)
    }
}

// Push the marble where the stick points, relative to where the camera looks.
// (The autopilot thinks in compass directions instead: east and north.)
if (!hasWon_) {
    Vec3 forward{-std::sin(cameraYaw_), 0, -std::cos(cameraYaw_)};
    Vec3 right{std::cos(cameraYaw_), 0, -std::sin(cameraYaw_)};
    if (isDemo) {
        Autopilot::Command command = autopilot_.steer(engine, level_);
        wish_ = command.push;
        if (command.jump) jumpBuffer_ = 0.15f;
        forward = Vec3{0, 0, -1};
        right = Vec3{1, 0, 0};
        if (simd::length(wish_) > 0.1f) hasMoved_ = true;
    }
    Vec3 push = right * wish_.x + forward * wish_.y;
    float control = body->isGrounded ? 1.0f : kAirControl;
    body->velocity += push * (kAcceleration * control * dt);

    // A speed limit on the ground plane only, so that falling stays fast.
    Vec3 flat{body->velocity.x, 0, body->velocity.z};
    float speed = simd::length(flat);
    if (speed > kMaxSpeed) {
        flat *= kMaxSpeed / speed;
        body->velocity = Vec3{flat.x, body->velocity.y, flat.z};
    }

    jumpBuffer_ -= dt;
    if (jumpBuffer_ > 0 && body->isGrounded) {
        body->velocity.y = kJumpSpeed;
        jumpBuffer_ = 0;
        engine.audio().play(sounds_.jump);
    }
}

"Avanti" significa lontano dalla camera, così i comandi restano naturali mentre la camera orbita.
In aria la biglia si può ancora dirigere, ma solo di poco.
E guarda il ramo isDemo: l'autopilota produce le stesse due cose che produce un giocatore, una direzione e un salto.
Poiché il gioco legge il suo input da due variabili e non dalla tastiera, sostituire il giocatore con un programma ha richiesto una manciata di righe.

Una piattaforma che porta il suo passeggero#

A metà percorso una piattaforma traghetta la biglia oltre un vuoto.
È un corpo cinematico: si muove, ma niente può spingerlo.

// The moving platform carries the marble across the gap between terrace and landing.
let ferryStart = Vec3(17, 2.25, -12.4), ferryEnd = Vec3(17, 2.25, -6.6)
level.ferry = builder.block("Ferry", center: ferryStart, size: Vec3(3, 0.5, 3), paint)
scene.add(level.ferry, RigidBody(type: .kinematic, friction: 1))       // it moves, but nothing can push it
scene.add(level.ferry, MovingPlatform(from: ferryStart, to: ferryEnd, period: 9))

// The moving platform carries the marble across the gap between terrace and landing.
Entity platform = builder.block("Ferry", Vec3{17, 2.25f, -12.4f}, Vec3{3, 0.5f, 3}, paint);
RigidBody ferryBody;
ferryBody.type = BodyType::Kinematic;       // it moves, but nothing can push it
ferryBody.friction = 1.0f;
scene.add(platform, ferryBody);
scene.add(platform, MovingPlatform{Vec3{17, 2.25f, -12.4f}, Vec3{17, 2.25f, -6.6f}, 9.0f});
level.ferry = platform;

Il modo che viene spontaneo per muoverla è scrivere una nuova posizione a ogni passo.
La biglia non la seguirebbe: per la fisica la piattaforma si starebbe teletrasportando, e un corpo che si teletrasporta non ha una velocità da trasmettere attraverso l'attrito.
Un corpo cinematico va mosso nel modo che la fisica capisce, con la sua velocità:

// Moving platforms: a kinematic body goes where its velocity takes it, so the
// platform is steered by setting the velocity that leads to where it should be next.
let time = Float(engine.time.elapsed)
scene.each(MovingPlatform.self, RigidBody.self) { _, platform, platformBody in
    let t = 0.5 - 0.5 * cos((time + dt) / platform.period * 2 * Float.pi)      // 0 -> 1 -> 0, easing at the ends
    let target = lerp(platform.from, platform.to, t)
    platformBody.velocity = (target - platformBody.position) / dt
}

// Moving platforms: a kinematic body goes where its velocity takes it, so the
// platform is steered by setting the velocity that leads to where it should be next.
float time = float(engine.time.elapsed);
scene.each<MovingPlatform, RigidBody>([&](Entity, MovingPlatform& platform, RigidBody& platformBody) {
    float t = 0.5f - 0.5f * std::cos((time + dt) / platform.period * 2.0f * kPi);      // 0 -> 1 -> 0, easing at the ends
    Vec3 target = lerp(platform.from, platform.to, t);
    platformBody.velocity = (target - platformBody.position) / dt;
});

Calcola dove deve trovarsi la piattaforma tra un passo, e imposta la velocità che ce la porta in un passo esatto.
La piattaforma segue con precisione il suo percorso, e la biglia che le sta sopra viene trasportata dall'attrito come qualsiasi oggetto appoggiato su uno in movimento.

Suono senza file audio#

Marble ha sei effetti sonori e nemmeno un file audio.
Ognuno viene calcolato all'avvio del gioco a partire da una forma d'onda, da un'altezza che può scivolare e da una durata:

func note(_ waveform: Waveform, _ frequency: Float, _ duration: Float, _ volume: Float) -> SynthParams {
    SynthParams(waveform: waveform, frequency: frequency, duration: duration, release: duration * 0.6, volume: volume)
}

// Two quick notes a fifth apart: the classic "got it" chime.
let collect = synthesizeSequence([note(.triangle, 880, 0.07, 0.35), note(.triangle, 1318.5, 0.22, 0.35)])

// A pitch that slides up reads as "going up"; down, as falling.
var jump = note(.sine, 260, 0.16, 0.4)
jump.frequencyEnd = 520

SynthParams note(Waveform waveform, float frequency, float duration, float volume) {
    SynthParams params;
    params.waveform = waveform;
    params.frequency = frequency;
    params.duration = duration;
    params.volume = volume;
    params.release = duration * 0.6f;
    return params;
}

// Then, in Sounds::make():

// Two quick notes a fifth apart: the classic "got it" chime.
sounds.collect = share(synthesizeSequence({note(Waveform::Triangle, 880.0f, 0.07f, 0.35f),
                                           note(Waveform::Triangle, 1318.5f, 0.22f, 0.35f)}));

// A pitch that slides up reads as "going up"; down, as falling.
SynthParams jump = note(Waveform::Sine, 260.0f, 0.16f, 0.4f);
jump.frequencyEnd = 520.0f;
sounds.jump = share(synthesize(jump));

L'engine sa caricare anche i file audio.
Ma per i suoni di un piccolo gioco basta una manciata di numeri, e così il repository resta libero da file con licenze poco chiare.

Riprodurre una clip significa consegnarla al mixer.
Il sistema operativo chiede audio a piccoli blocchi, molte volte al secondo, su un thread tutto suo.
Ogni volta il mixer scorre il suo elenco di suoni in riproduzione, legge il pezzo successivo di ogni clip, lo scala secondo volume e pan, e somma tutto.
Un mixer software non è altro che questo.

La velocità a cui una clip viene letta è il suo pitch, e può cambiare mentre il suono viene riprodotto.
Due effetti del gioco si basano su questo.
Ogni gemma suona lo stesso rintocco un po' più acuto della precedente, così raccoglierle dà la sensazione di salire.
E il rombo della biglia che rotola è un secondo di rumore, in loop, riprodotto a circa un decimo della sua velocità:

// The rumble gets louder and higher with speed, and stops in the air.
let rolling = body.isGrounded ? saturate(speed / maxSpeed) : 0
engine.audio.mixer.setVolume(rollSound, 0.16 * rolling)
engine.audio.mixer.setPitch(rollSound, 0.08 + 0.1 * rolling)

// The rumble gets louder and higher with speed, and stops in the air.
float rolling = body->isGrounded ? saturate(speed / kMaxSpeed) : 0.0f;
engine.audio().mixer().setVolume(rollSound_, 0.16f * rolling);
engine.audio().mixer().setPitch(rollSound_, 0.08f + 0.1f * rolling);

Il suono non parte e non si ferma mai.
Viene riprodotto di continuo, ed è semplicemente muto quando la biglia sta ferma o vola.

L'interfaccia#

Il contatore, l'orologio e i messaggi sono disegnati con il canvas 2D dell'engine, nato dai capitoli Rendering del testo e Un gioco 2D.
Lavora in immediate mode: non ci sono oggetti etichetta da creare e tenere aggiornati.
A ogni frame draw dice che cosa deve esserci a schermo:

// Gems, top left.

Le posizioni sono in punti a partire dall'angolo in alto a sinistra, e i colori sono i valori sRGB che mostra un selettore di colore.
Il canvas trasforma le chiamate in triangoli, e il renderer li disegna a fine frame con il minor numero di draw call che le texture permettono.

Il testo viene da un atlas di font a distance field, ed è per questo che size può essere un numero qualsiasi.
Quando una gemma viene raccolta, collectPulse salta a uno e si spegne, e il contatore si gonfia da 22 a 30 punti e torna indietro senza mai apparire sfocato.

Un gioco che gioca da solo#

Avvia il gioco con --demo e nessuno deve toccarlo.
Un autopilota fa rotolare la biglia attraverso ogni gemma, aspetta il traghetto, ci sale, salta per prendere la gemma sopra di esso e finisce al traguardo.

È un elenco di waypoint e una sola regola di guida.
La regola legge ciò che vedrebbe un giocatore, cioè dove sono la biglia e il traghetto, e restituisce ciò che un giocatore farebbe:

// Steering: decide the velocity we would like (toward the target, slower when close),
// then push in proportion to how far the real velocity is from it. On the ferry the
// velocity we want is the ferry's own, plus whatever keeps us near its center.
let toTarget = target - marble.position
var wanted = Vec3(toTarget.x, 0, toTarget.z) * 2.5
let wantedSpeed = simd_length(wanted)
if wantedSpeed > waypoint.speed { wanted *= waypoint.speed / wantedSpeed }
if waypoint.action == .board || waypoint.action == .ride { wanted += ferry.velocity }
let correction = (wanted - marble.velocity) * 0.6
command.push = Vec2(correction.x, -correction.z)       // north is -z
let length = simd_length(command.push)
if length > 1 { command.push /= length }
return command

// Steering: decide the velocity we would like (toward the target, slower when close),
// then push in proportion to how far the real velocity is from it. On the ferry the
// velocity we want is the ferry's own, plus whatever keeps us near its center.
Vec3 toTarget = target - marble->position;
Vec3 wanted = Vec3{toTarget.x, 0, toTarget.z} * 2.5f;
float wantedSpeed = simd::length(wanted);
if (wantedSpeed > waypoint.speed) wanted *= waypoint.speed / wantedSpeed;
if (waypoint.action == Action::Board || waypoint.action == Action::Ride) wanted += ferry->velocity;
Vec3 correction = (wanted - marble->velocity) * 0.6f;
command.push = Vec2{correction.x, -correction.z};  // north is -z
float length = simd::length(command.push);
if (length > 1.0f) command.push /= length;
return command;

Una demo è piacevole da guardare, ma non è per questo che l'autopilota esiste.
Insieme a un'altra opzione diventa un test dell'intero engine:

swift run Marble --demo --capture run.png --frames 2400

./build/marble --demo --capture run.png --frames 2400

Con --capture l'engine non apre né una finestra né un dispositivo audio.
Disegna in una texture, fa avanzare il tempo di un sessantesimo di secondo esatto per frame, qualunque sia stata la durata reale del frame, e dopo il numero di frame indicato salva l'ultimo come PNG.
L'esecuzione è identica ogni volta.

Test che non hanno bisogno di una GPU#

La maggior parte di un engine non è grafica, e tutto ciò che non è grafica si può testare senza una GPU: la matematica, la scena, l'input, la generazione delle mesh, le collisioni e la fisica, l'adattamento delle cascate di ombre, il layout delle struct condivise, la sintesi dei suoni e il mixer.
L'engine tiene queste parti libere da Metal proprio perché si possano testare.

func testABallFallsBouncesAndComesToRestOnTheFloor() {
    let scene = Scene(), physics = Physics()
    addStaticBox(scene, Vec3(0, -0.5, 0), Vec3(10, 0.5, 10))
    let ball = addBall(scene, Vec3(0, 3, 0))
    scene[ball, RigidBody.self]?.restitution = 0.5

    run(physics, scene, seconds: 0.5)
    XCTAssertLessThan(scene[ball, RigidBody.self]!.position.y, 3)        // it fell
    run(physics, scene, seconds: 6)
    let body = scene[ball, RigidBody.self]!
    XCTAssertEqual(body.position.y, 0.5, accuracy: 0.02)                 // resting on the floor, not sinking into it
    XCTAssertLessThan(simd_length(body.velocity), 0.2)
    XCTAssertTrue(body.isGrounded)
    XCTAssertEqual(body.groundNormal.y, 1, accuracy: 1e-3)
}

TEST(a_ball_falls_bounces_and_comes_to_rest_on_the_floor) {
    Scene scene;
    Physics physics;
    addStaticBox(scene, Vec3{0, -0.5f, 0}, Vec3{10, 0.5f, 10});
    Entity ball = addBall(scene, Vec3{0, 3, 0});
    scene.get<RigidBody>(ball)->restitution = 0.5f;

    run(physics, scene, 0.5f);
    CHECK(scene.get<RigidBody>(ball)->position.y < 3);                   // it fell
    run(physics, scene, 6.0f);
    const RigidBody& body = *scene.get<RigidBody>(ball);
    CHECK_NEAR(body.position.y, 0.5, 0.02);                              // resting on the floor, not sinking into it
    CHECK(simd::length(body.velocity) < 0.2f);
    CHECK(body.isGrounded);
    CHECK_NEAR(body.groundNormal.y, 1, 1e-3);
}

Che cosa costruire dopo#

Il modo migliore di capire un engine è fargli fare qualcosa che ancora non fa.
Qualche idea, più o meno dalla più facile alla più difficile:

  • Un trampolino.
    Un trigger che imposta la velocità verso l'alto della biglia.
    Tutto ciò che ti serve è in questo capitolo.
  • Un secondo livello.
    buildLevel è un elenco di scatole; scrivine un altro e passaci quando viene raggiunto il traguardo.
  • Una lampada sul traghetto.
    Fai di una luce puntiforme una figlia della piattaforma mobile, e guarda Transform.parent al lavoro.
  • Suoni nello spazio.
    engine.playSoundAt prende una posizione e imposta volume e pan in base a dove si trova la camera.
    Usalo per il tonfo delle casse.
  • Ombre per uno spot.
    Un'altra shadow map, con una proiezione prospettica, accanto alle cascate.
  • Un formato di file per i livelli.
    Leggi le scatole da un file di testo, poi fai in modo che il gioco lo ricarichi quando cambia, come già fanno gli shader.

Ognuna di queste tocca una parte dell'engine e lascia stare il resto.
È a questo, più che a qualsiasi singola tecnica, che serve la disposizione descritta in questi capitoli.

L'ultima idea dell'elenco è stata portata più in là di un file di testo: il prossimo capitolo parla dell'editor di scene dell'engine.
