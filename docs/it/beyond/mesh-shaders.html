Mesh shader#

Una vertex function riceve un vertice e restituisce un vertice.
Non può creare geometria, e non può buttare via un oggetto intero.
Una pipeline con mesh shader sostituisce lo stadio di vertice con due stadi programmabili che sanno fare entrambe le cose, interamente sulla GPU.
È la risposta di Metal ai geometry shader di altre API, e da Metal 4 è anche il sostituto consigliato della tassellazione.

Due nuovi stadi#

  • L'object stage gira una volta per oggetto, o per cluster di triangoli.
    Decide se quell'oggetto è visibile, quanto dettaglio merita e quante mesh lanciare per lui.
    Può passare allo stadio successivo un piccolo blocco di dati, il payload.
    Questo stadio è facoltativo.
  • Il mesh stage gira una volta per mesh e scrive i vertici, gli indici e il numero di primitive di una piccola mesh.
    Poi il rasterizer prosegue come al solito, e la fragment function non cambia.

Entrambi gli stadi girano come i compute kernel: lanci una griglia di threadgroup, e ogni thread conosce il proprio indice.

Una piccola mesh di qualche centinaio di triangoli al massimo si chiama meshlet.
Dividere in anticipo un modello grande in meshlet, e farne il culling nell'object stage, è l'uso principale di questa pipeline: i triangoli che non si possono vedere non arrivano mai al rasterizer.

La mesh function#

Il tipo di uscita è un template mesh: il tipo dei vertici, il tipo dei dati per primitiva, il numero massimo di vertici e di primitive, e la topologia.

#include <metal_stdlib>
using namespace metal;

struct VertexOut {
    float4 position [[position]];
    float3 color;
};

struct PrimitiveOut {
    float shade;
};

using QuadMesh = metal::mesh<VertexOut, PrimitiveOut, 4, 2, metal::topology::triangle>;

struct Uniforms {
    float4x4 viewProjection;
    float time;
};

[[mesh]] void mesh_main(QuadMesh output,
                        constant Uniforms &uniforms [[buffer(0)]],
                        uint3 group [[threadgroup_position_in_grid]],
                        uint thread [[thread_index_in_threadgroup]]) {
    // One threadgroup makes one quad. Its position in the grid places the quad.
    float3 center = float3(float(group.x) - 16.0, 0.0, float(group.y) - 16.0) * 1.5;

    // Four threads: each writes one vertex.
    float2 corner = float2(thread & 1u, thread >> 1u) - 0.5;
    VertexOut v;
    v.position = uniforms.viewProjection * float4(center + float3(corner.x, sin(uniforms.time + center.x) * 0.3, corner.y), 1.0);
    v.color = float3(corner + 0.5, 0.5);
    output.set_vertex(thread, v);

    if (thread == 0u) {
        // Two triangles: 0-1-2 and 2-1-3.
        output.set_index(0, 0); output.set_index(1, 1); output.set_index(2, 2);
        output.set_index(3, 2); output.set_index(4, 1); output.set_index(5, 3);
        PrimitiveOut p;
        p.shade = 1.0;
        output.set_primitive(0, p);
        p.shade = 0.8;
        output.set_primitive(1, p);
        output.set_primitive_count(2);
    }
}

set_primitive_count è ciò che rende flessibile lo stadio: scrivi 0 e la mesh non produce niente.
La fragment function riceve i dati dei vertici interpolati e, se li chiede, i dati per primitiva.

struct FragmentIn {
    VertexOut vertex;
    PrimitiveOut primitive;
};

fragment float4 fragment_main(FragmentIn in) {
    return float4(in.vertex.color * in.primitive.shade, 1.0);
}

La pipeline e la draw call#

La pipeline usa un suo tipo di descriptor.
Non c'è vertex descriptor, perché non ci sono vertex buffer: la mesh function legge i buffer che vuole.

let descriptor = MTLMeshRenderPipelineDescriptor()
descriptor.meshFunction = library.makeFunction(name: "mesh_main")
descriptor.fragmentFunction = library.makeFunction(name: "fragment_main")
descriptor.colorAttachments[0].pixelFormat = view.colorPixelFormat
descriptor.depthAttachmentPixelFormat = .depth32Float

let (pipelineState, _) = try device.makeRenderPipelineState(descriptor: descriptor, options: [])

MTL::MeshRenderPipelineDescriptor* descriptor = MTL::MeshRenderPipelineDescriptor::alloc()->init();
descriptor->setMeshFunction(library->newFunction(MTLSTR("mesh_main")));
descriptor->setFragmentFunction(library->newFunction(MTLSTR("fragment_main")));
descriptor->colorAttachments()->object(0)->setPixelFormat(MTL::PixelFormatBGRA8Unorm);
descriptor->setDepthAttachmentPixelFormat(MTL::PixelFormatDepth32Float);

NS::Error* error = nullptr;
MTL::RenderPipelineState* pipelineState =
    device->newRenderPipelineState(descriptor, MTL::PipelineOptionNone, nullptr, &error);
descriptor->release();

I buffer si collegano stadio per stadio con setMeshBuffer e setObjectBuffer, e la draw call lancia dei threadgroup invece di contare vertici.

encoder.setRenderPipelineState(pipelineState)
encoder.setMeshBuffer(uniformBuffer, offset: 0, index: 0)
encoder.drawMeshThreadgroups(
    MTLSize(width: 32, height: 32, depth: 1),                    // 1,024 quads
    threadsPerObjectThreadgroup: MTLSize(width: 1, height: 1, depth: 1),
    threadsPerMeshThreadgroup: MTLSize(width: 4, height: 1, depth: 1))

encoder->setRenderPipelineState(pipelineState);
encoder->setMeshBuffer(uniformBuffer, 0, 0);
encoder->drawMeshThreadgroups(
    MTL::Size(32, 32, 1),                 // 1,024 quads
    MTL::Size(1, 1, 1),                   // threads per object threadgroup
    MTL::Size(4, 1, 1));                  // threads per mesh threadgroup

Senza una object function, la griglia che passi è la griglia dei threadgroup di mesh.

Aggiungere l'object stage#

Con una object function la griglia nella draw call è la griglia dei threadgroup di object, e ognuno di essi decide quanti threadgroup di mesh lanciare.

struct Payload {
    float3 origin;
    uint detail;
};

[[object]] void object_main(object_data Payload &payload [[payload]],
                            mesh_grid_properties grid,
                            constant Uniforms &uniforms [[buffer(0)]],
                            uint3 group [[threadgroup_position_in_grid]]) {
    float3 origin = float3(float(group.x) - 4.0, 0.0, float(group.y) - 4.0) * 12.0;

    // Cull: is the center of this cluster inside the view volume?
    float4 clip = uniforms.viewProjection * float4(origin, 1.0);
    bool visible = clip.w > 0.0 && abs(clip.x) < clip.w * 1.3 && abs(clip.y) < clip.w * 1.3;
    if (!visible) {
        grid.set_threadgroups_per_grid(uint3(0, 0, 0));           // launch nothing
        return;
    }

    // Level of detail: fewer quads for far clusters.
    uint detail = clip.w < 30.0 ? 8u : (clip.w < 80.0 ? 4u : 2u);
    payload.origin = origin;
    payload.detail = detail;
    grid.set_threadgroups_per_grid(uint3(detail, detail, 1));
}

La mesh function riceve il payload con const object_data Payload &payload [[payload]].
Nel pipeline descriptor imposta objectFunction, payloadMemoryLength (la dimensione della struct del payload) e maxTotalThreadgroupsPerMeshGrid (qui 64).

Quando usarli#

  • Culling dei meshlet.
    Culling per cluster contro il frustum, delle facce posteriori e per occlusione, nei modelli densi.
  • Geometria procedurale.
    Erba, capelli, particelle come rettangoli, patch di terreno: geometria che altrimenti richiederebbe un compute pass e un buffer intermedio.
  • Livello di dettaglio sulla GPU, scelto per cluster e per frame.
  • Sostituire i geometry shader nei porting da altre API, e la tassellazione in Metal 4.

I mesh shader richiedono Metal 3: i Mac con Apple silicon, e gli iPhone e iPad con chip A14 o successivo.
Controlla device.supportsFamily(.metal3).
Per un normale modello disegnato una volta la pipeline con i vertici è più semplice e altrettanto veloce.

Esercizi#

  • Cambia il numero di rettangoli modificando solo la dimensione della griglia nella draw call.
    Mostra la soluzione

    Passa MTLSize(width: 64, height: 64, depth: 1) e ottieni 4.096 rettangoli.
    Non cambia nient'altro, perché ogni threadgroup calcola la propria posizione da threadgroup_position_in_grid.
    Regola lo scarto - 16.0 per tenere centrato il campo.

  • Fai restituire alla mesh function zero primitive per un rettangolo sì e uno no, come una scacchiera.
    Mostra la soluzione

    Decidi in base alla posizione del gruppo e scrivi il conteggio di conseguenza.
    I vertici scritti per una mesh con zero primitive vengono ignorati.

    bool keep = ((group.x + group.y) & 1u) == 0u;
output.set_primitive_count(keep ? 2 : 0);
  • Aggiungi l'object stage e colora ogni cluster in base al suo livello di dettaglio.
    Mostra la soluzione

    Metti il livello di dettaglio nel payload, leggilo nella mesh function e trasformalo in un colore.

    float3 tint = payload.detail == 8u ? float3(0.2, 0.9, 0.3)
            : payload.detail == 4u ? float3(0.9, 0.8, 0.2) : float3(0.9, 0.3, 0.2);
v.color = tint;

    I cluster vicini sono verdi, quelli intermedi gialli e quelli lontani rossi, e puoi guardare le fasce spostarsi insieme alla camera.
