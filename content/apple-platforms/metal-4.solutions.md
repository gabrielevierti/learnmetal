Four things. It stored the binding in the encoder's own table, which Metal 4 replaces with a table you size and own. It retained the texture until the command buffer completed; now you must keep it alive. It made the texture resident for the GPU; now a residency set does. And through hazard tracking it made sure an earlier pass that wrote the texture finished first; now you add a barrier. Each is a small cost per call that Metal 4 lets you pay once, or not at all.
---
The order that works: create the `MTL4CommandQueue`, the command buffer and three allocators; build the pipeline with an `MTL4Compiler`; create an argument table with one buffer binding and set the vertex buffer's address; create a residency set with the vertex buffer and add it, and the layer's own set, to the queue. In the draw method take `currentMTL4RenderPassDescriptor`, begin the command buffer, encode, end, and commit between `waitForDrawable` and `signalDrawable`. If the triangle is missing, check the residency set first.
